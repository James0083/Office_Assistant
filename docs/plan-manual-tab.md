# 기획: 메뉴얼 탭

상황별로 "무엇을, 어떤 순서로 해야 하는지" 를 정리해 두고, 그 상황이 오면 보면서 따라 하는 탭.
예: 신입생 등록, 수강료 미납 안내, 퇴원 처리, 보강 일정 잡기, 학부모 상담 요청 대응

## 1. 화면

다른 탭(템플릿·메모)과 같은 **왼쪽 목록 + 오른쪽 내용** 구조. 검색(제목/본문/제목+본문)도 똑같이 쓴다.
오른쪽은 **보기 모드**가 기본이고, `편집` 을 눌러야 고칠 수 있다 (실수로 고치는 것 방지, 관리자 기능과 연결 → [plan-admin.md](plan-admin.md)).

### 보기 모드

```
┌ 신입생 등록 ───────────────────────────────── [편집] ┐
│ 상담 후 등록이 확정되면 당일 안에 처리               │  ← 설명 (선택)
│                                                      │
│ ☐ 1  등록 신청서 받기                                │
│      🔗 등록 신청서 양식 (열기)                       │
│                                                      │
│ ☐ 2  학부모에게 등록 완료 문자 보내기                │
│      ┌ 예시 문구 ─────────────────────── [복사] ┐   │
│      │ 안녕하세요, 수학의힘입니다. ...          │   │
│      └──────────────────────────────────────────┘   │
│                                                      │
│ ☐ 3  출석부에 학생 추가                              │
│      🔗 출석부 (열기)   📄 반 배정표.xlsx (열기)     │
│                                                [초기화] │
└──────────────────────────────────────────────────────┘
```

- **체크박스**: 지금 어디까지 했는지 표시용. 저장하지 않는다 (다른 메뉴얼로 가거나 앱을 끄면 지워짐, `초기화` 로 바로 지울 수도 있음).
  → 공유 데이터에 넣지 않아 다른 사람 화면과 섞이지 않는다.
- **예시 문구**: `복사` 한 번으로 클립보드에. 템플릿처럼 `{변수}` 가 있으면 미리보기 창을 띄워 값을 채운 뒤 복사 (2단계에서).
- **링크**: `열기` 를 누르면 웹 주소는 브라우저로, 파일은 기본 프로그램으로 연다.

### 편집 모드

```
상황 (제목)  [ 신입생 등록                         ]
설명 (선택)  [ 상담 후 등록이 확정되면 당일 안에 처리 ]

┌ 단계 1 ──────────────────────────── [↑][↓][삭제] ┐
│ 할 일   [ 등록 신청서 받기                       ] │
│ ☐ 예시 문구 사용                                  │
│ 링크    [등록 신청서 양식] [https://forms.gle/…] [×]│
│         + 링크 추가                                │
└───────────────────────────────────────────────────┘
┌ 단계 2 ──────────────────────────── [↑][↓][삭제] ┐
│ 할 일   [ 학부모에게 등록 완료 문자 보내기       ] │
│ ☑ 예시 문구 사용                                  │
│   [ 안녕하세요, 수학의힘입니다. ...              ] │
│ 링크    + 링크 추가                                │
└───────────────────────────────────────────────────┘
               + 단계 추가
                                   [삭제] [저장]
```

| 필드 | 필수 | 설명 |
|---|---|---|
| 상황 (제목) | ✅ | 목록에 보이는 이름. 다른 메뉴얼과 겹치면 안 됨 (지금 템플릿·메모와 같은 규칙) |
| 설명 | | 언제 쓰는 메뉴얼인지 한두 줄 |
| 단계 → 할 일 | ✅ | 이 단계에서 할 행동. 여러 줄 가능 |
| 단계 → 예시 문구 | 토글 | 켜면 입력칸이 나타남. 끄면 내용은 남겨 두되 보기 모드에 안 보임 (실수로 꺼도 안 사라지게) |
| 단계 → 링크 | 여러 개 | `이름` + `주소`. 이름을 비우면 주소를 그대로 보여줌 |

- 단계 순서는 ↑↓ 로 바꾼다 (끌어서 옮기기는 2단계에서).
- 단계가 하나도 없으면 저장할 수 없다. 할 일이 빈 단계는 저장할 때 빼고 알려준다.

## 2. 링크 주소 규칙

| 입력 | 처리 |
|---|---|
| `https://…`, `http://…` | 기본 브라우저로 열기 |
| `파일/등록신청서.hwp` 처럼 **앱 폴더 기준 상대 경로** | 앱 폴더(= `data.json` 폴더) 기준으로 찾아서 기본 프로그램으로 열기 |
| `/Users/…`, `C:\…` 같은 절대 경로 | 허용하되 저장할 때 경고: "다른 컴퓨터에서는 열리지 않을 수 있습니다" |
| 그 밖의 것 (`javascript:`, 실행 파일 등) | 저장 안 됨 |

공유 폴더는 맥과 Windows 에서 경로가 다르므로 (`/Volumes/공유/…` vs `Z:\…`) **상대 경로를 권장**한다.
편집 화면에 `파일 선택` 버튼을 두고, 앱 폴더 안의 파일을 고르면 상대 경로로 자동 입력한다.
없는 파일이면 보기 모드에서 링크 옆에 ⚠️ 표시.

## 3. 데이터 형식 (`data.json`)

```json
{
  "notes": [...],
  "templates": [...],
  "manuals": [
    {
      "name": "신입생 등록",
      "content": "상담 후 등록이 확정되면 당일 안에 처리",
      "steps": [
        {
          "action": "등록 신청서 받기",
          "example_on": false,
          "example": "",
          "links": [{ "label": "등록 신청서 양식", "url": "https://forms.gle/..." }]
        },
        {
          "action": "학부모에게 등록 완료 문자 보내기",
          "example_on": true,
          "example": "안녕하세요, 수학의힘입니다. ...",
          "links": []
        }
      ]
    }
  ]
}
```

- `name`·`content` 를 다른 종류와 똑같이 두어 **검색·목록·충돌 처리 코드를 그대로 재사용**한다 (설명이 `content`).
- 저장 단위는 지금처럼 **메뉴얼 하나**. 단계 하나만 고쳐도 메뉴얼 전체가 한 항목이다.
- 예전 버전 앱은 `manuals` 를 모르지만 저장할 때 그대로 남겨 둔다 → **부 버전(1.x.0)** 으로 배포 가능 ([VERSIONING.md](VERSIONING.md)).

## 4. 구현 범위

### `app.py`
- `KINDS` 에 `"manuals"` 추가, `DEFAULT_DATA` 에 예시 메뉴얼 1개
- `normalize()` 에 메뉴얼 모양 추가 (`steps` → `action`, `example_on`, `example`, `links`)
- 새 API `open_link(url)`: 위 2번 규칙대로 검사 후 열기 (macOS `open`, Windows `os.startfile`). 검사는 **반드시 파이썬에서** (화면에서 보낸 값을 그대로 실행하지 않음)
- 새 API `pick_file()`: 파일 선택 창 → 앱 폴더 기준 상대 경로 반환

### `ui.html`
- 탭 버튼 `메뉴얼` 추가
- `collection()` 은 "이름 + 본문 + (변수)" 편집기라 단계 블록을 넣기 어렵다 → **목록·검색·저장·충돌 처리 부분을 함수로 떼어** 템플릿·메모·메뉴얼이 같이 쓰고, 오른쪽 편집기만 종류별로 만든다
- 보기 모드 / 편집 모드 전환, 단계 블록 추가·삭제·순서 변경, 예시 문구 토글, 링크 행
- 저장 안 한 변경 확인(`dirty`)·충돌 대화상자는 지금 것을 그대로 사용

### 테스트
- 백엔드: 메뉴얼 저장·충돌·이름 중복, `open_link` 주소 검사 (허용/거부 목록)
- 화면: 단계 추가 → 저장 → 다시 불러왔을 때 순서·토글·링크 유지

## 5. 단계별 진행 제안

| 단계 | 내용 |
|---|---|
| 1차 (1.1.0) | 위 1~4 전부. 링크는 웹 주소 + 상대 경로 파일 |
| 2차 | 예시 문구에 `{변수}` + 미리보기, 예시 문구를 기존 **문자 템플릿과 연결**("템플릿에서 가져오기"), 끌어서 순서 바꾸기, 메뉴얼 분류(태그) |
| 3차 | 관리자만 편집 ([plan-admin.md](plan-admin.md)) |

## 6. 정해야 할 것

- [ ] 처음 넣어 둘 예시 메뉴얼 (실제 학원 업무 한두 개로 하면 바로 쓸 수 있음)
- [ ] 체크 상태를 정말 저장 안 해도 되는지 (예: "오늘 신입생 A 등록 진행 중" 을 다음 날까지 남겨야 하는 경우가 있는지)
- [ ] 메뉴얼을 처음부터 관리자만 편집하게 할지 (3차를 1차에 합칠지)
