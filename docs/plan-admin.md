# 기획: 관리자 기능

메뉴얼이나 민감한 정보를 **관리자만 수정**할 수 있게 한다.

## 1. 먼저 알아야 할 한계

데이터는 공유 폴더의 `data.json` 이라는 **그냥 텍스트 파일**이다.
폴더에 접근할 수 있는 사람은 앱을 거치지 않고 메모장으로 파일을 열어 **읽고 고칠 수 있다.**

그래서 앱 안의 관리자 기능만으로 할 수 있는 것과 없는 것이 나뉜다.

| 목표 | 앱만으로 | 방법 |
|---|---|---|
| 직원이 앱에서 **실수로** 고치는 것 막기 | ✅ 가능 | 관리자 비밀번호 + 잠금 (방안 A) |
| 누가 `data.json` 을 **몰래 고쳤는지 알아채기** | ✅ 가능 | 관리자 서명 (방안 A 에 추가) |
| `data.json` 을 직접 고치는 것 **자체를 막기** | ❌ 불가 | 폴더 권한 (방안 C) |
| 민감한 내용을 **보지도 못하게** 하기 | ⚠️ 암호화 필요 | 방안 B |

> "수정 금지" 와 "열람 금지" 는 다른 문제다. 계좌번호처럼 **어차피 학부모에게 보내는 정보**는 수정만 막으면 되고,
> 직원 개인정보·사이트 비밀번호처럼 **보면 안 되는 정보**는 암호화(방안 B)가 필요하다. 어떤 정보가 어디에 해당하는지 먼저 정해야 한다.

## 2. 방안 비교

### 방안 A — 관리자 비밀번호 + 잠금 (권장, 1차)

- 관리자가 처음 한 번 비밀번호를 정한다. `data.json` 에는 **비밀번호 대신 해시만** 저장 (PBKDF2, 파이썬 기본 `hashlib` → 새 패키지 필요 없음)
- 항목마다 🔒 `잠금` 을 켤 수 있다. 메뉴얼은 기본으로 잠금
- 잠긴 항목은 누구나 **볼 수는** 있지만 `편집`·`삭제` 를 누르면 비밀번호를 묻는다
- 맞으면 그 앱 창에서 **관리자 모드**가 켜지고, 10분 동안 아무것도 안 하거나 앱을 끄면 꺼진다
- **검사는 파이썬(`save_item`/`delete_item`)에서 한다.** 화면에서만 막으면 개발자 도구 등으로 우회 가능

**관리자 서명 (몰래 고친 것 알아채기)**
- 관리자가 잠긴 항목을 저장할 때, 비밀번호에서 만든 키로 내용에 서명(HMAC)을 붙인다
- 누군가 메모장으로 잠긴 항목을 고치면 서명이 안 맞는다 → 관리자가 로그인할 때 "⚠️ 관리자가 저장한 내용과 다릅니다" 표시
- 서명 검사에도 비밀번호가 필요하므로 **검사는 관리자 로그인 때** 한다 (일반 직원 화면에서는 검사 못 함).
  누구나 검사할 수 있게 하려면 공개키 서명(Ed25519)이 필요한데, `cryptography` 패키지가 든다 → 방안 B 를 할 때 같이 검토
- 비밀번호 해시를 지우고 새로 만들어도, 예전 서명들이 전부 안 맞게 되어 티가 난다

| 장점 | 단점 |
|---|---|
| 새 패키지 없음, 지금 구조에 자연스럽게 붙음 | 파일 직접 수정은 못 막음 (알아채기만) |
| 직원이 쓰기에 단순 (잠긴 것만 비밀번호) | 비밀번호를 잊으면 복구 절차 필요 (아래 5번) |

### 방안 B — 민감 정보 암호화 (필요할 때, 2차)

- `🔐 비공개` 로 지정한 메모는 내용을 암호화해서 저장. 관리자 비밀번호를 넣어야 보인다
- `cryptography` 패키지 필요 (Fernet, 앱 용량 수 MB 증가)
- 비밀번호를 잊으면 **내용을 되살릴 방법이 없다** → 복구 코드를 반드시 따로 보관
- 방안 A 의 비밀번호를 같이 쓴다

### 방안 C — 폴더 권한 (함께 쓰면 가장 확실)

NAS·Windows 공유·Google Drive 등에서 폴더 권한을 나눈다.

```
공유폴더/
├─ 수학의힘 행정도우미.app / .exe
├─ data.json          ← 모두 읽기·쓰기 (템플릿, 일반 메모)
└─ 관리자/
   └─ admin.json      ← 관리자만 쓰기, 나머지는 읽기 전용 (메뉴얼, 잠긴 메모)
```

- 앱은 두 파일을 합쳐서 보여주고, `admin.json` 에 쓸 수 없으면 해당 항목을 자동으로 읽기 전용으로 표시
- 운영체제가 막아 주므로 **파일 직접 수정도 막힌다**
- 단점: 공유 폴더 서비스에서 권한 설정을 해야 하고, 서비스마다 방법이 다름. 앱 코드도 파일 두 개를 다루도록 바뀜

### 방안 D — 직원별 계정

누가 무엇을 바꿨는지 기록까지 남길 수 있지만, 이 규모(학원 행정용·소수 인원)에는 과하다. **하지 않는 것을 권장.**

## 3. 권장안

1. **1차: 방안 A** (비밀번호 + 잠금 + 서명). 메뉴얼은 기본 잠금, 메모·템플릿은 항목별로 선택
2. 보면 안 되는 정보가 실제로 생기면 **2차: 방안 B**
3. 공유 폴더 권한을 설정할 수 있는 환경이면 **방안 C** 를 함께 검토

## 4. 화면

- 상단 오른쪽에 `🔓 관리자` 버튼. 관리자 모드일 때는 `🔑 관리자 모드 (남은 시간 8분)` + `끄기`
- 목록에서 잠긴 항목 이름 옆에 🔒
- 잠긴 항목의 편집기: 입력칸 읽기 전용 + `편집하려면 관리자 로그인` 안내
- 관리자 모드일 때만 보이는 것: 항목별 `잠금` 토글, `관리자 설정`(비밀번호 바꾸기, 자동 꺼짐 시간)
- 서명이 안 맞는 항목 (관리자 모드에서만 보임): ⚠️ 표시 + "확인 후 다시 저장(서명 갱신)" 버튼

## 5. 비밀번호 분실

- 처음 비밀번호를 정할 때 **복구 코드**(예: 16자리)를 한 번 보여주고, 종이에 적어 두게 한다 (해시만 저장)
- 복구 코드로 새 비밀번호를 정할 수 있다
- 복구 코드도 없으면: `data.json` 에서 관리자 정보를 지우면 초기화된다. 대신 모든 잠긴 항목의 서명이 안 맞게 되므로, 새 관리자가 내용을 확인하고 다시 저장해야 한다. (방안 B 의 암호화된 내용은 복구 불가)

## 6. 데이터 형식 (방안 A)

```json
{
  "admin": {
    "hash": "pbkdf2_sha256$600000$<salt>$<hash>",
    "recovery_hash": "pbkdf2_sha256$600000$<salt>$<hash>",
    "sig_salt": "<base64>",
    "timeout_min": 10
  },
  "notes": [
    { "name": "기본 정보", "content": "...", "locked": true, "sig": "<hmac>" }
  ],
  "manuals": [
    { "name": "신입생 등록", "steps": [...], "locked": true, "sig": "<hmac>" }
  ]
}
```

- `locked`, `sig` 는 항목에 붙는 새 필드. 서명 대상은 `locked`·`sig` 를 뺀 항목 내용
- `admin` 이 없으면 관리자 기능이 꺼진 상태 (지금과 똑같이 동작)

## 7. 구현 범위 (방안 A)

### `app.py`
- `Api.admin_setup(pw)` → 복구 코드 반환 / `Api.admin_login(pw)` / `Api.admin_logout()` / `Api.admin_reset(recovery, new_pw)`
- 관리자 여부는 **파이썬의 `Api` 객체 안에만** 둔다 (`self._admin_until`). 화면이 "나 관리자야" 라고 보내는 값은 믿지 않는다
- 지금 `normalize()` 는 `name`·`content`·`vars` 외의 필드를 버린다 → `locked` 는 남기고, `sig` 는 화면에서 온 값을 버리고 파이썬이 직접 계산해 넣도록 바꾼다
- `save_item` / `delete_item`: 디스크의 항목이 `locked` 이거나, 새로 저장할 항목을 `locked` 로 만들려 하면 → 관리자 아니면 `UserError("관리자만 수정할 수 있습니다")`
- 관리자가 잠긴 항목을 저장하면 `sig` 계산해서 함께 저장. 관리자 모드일 때 `load` 하면 서명 검사 결과를 항목마다 붙여 보냄 (`sig_ok`)
- 서명 키는 로그인할 때 비밀번호로 만들어 메모리에만 두고, 관리자 모드가 꺼지면 지운다
- 로그인 시도 제한 (예: 5번 틀리면 1분 대기)

### `ui.html`
- 위 4번 화면
- 잠긴 항목은 입력칸 비활성화 (실제 차단은 파이썬, 화면은 안내용)

### 테스트
- 관리자 아님 → 잠긴 항목 저장/삭제/잠금 해제 거부, 일반 항목은 그대로 가능
- 관리자 → 저장 시 서명 생성, 파일 직접 수정 후 관리자 로그인 시 `sig_ok == false`
- 자동 꺼짐 시간, 로그인 시도 제한, 복구 코드로 재설정

## 8. 배포할 때 주의 — **주 버전 (2.0.0)**

예전 버전 앱은 `locked` 를 모르므로 **잠긴 항목도 그냥 고칠 수 있다.**
관리자 기능이 들어간 버전은 **주 버전**으로 올리고, 모든 컴퓨터의 앱을 한꺼번에 바꾼다 ([VERSIONING.md](VERSIONING.md)).

이후를 위해 이번에 `data.json` 에 `"min_app_version"` 을 넣고, 앱이 자기 버전보다 높으면
"새 버전 앱이 필요합니다" 를 띄우고 **읽기 전용**으로 열리게 해 두면, 다음 주 버전부터는 예전 앱이 데이터를 망칠 걱정이 없다.

## 9. 정해야 할 것

- [ ] "민감한 정보" 가 구체적으로 무엇인지 — 수정만 막으면 되는지(방안 A), 보지도 못하게 해야 하는지(방안 B)
- [ ] 관리자는 한 명인지 여러 명인지 (여러 명이면 비밀번호 공유로 충분한지)
- [ ] 공유 폴더가 어디인지 (NAS / Windows 공유 / Google Drive / Dropbox …) → 방안 C 가능 여부
- [ ] 메뉴얼 탭과 같이 배포할지, 따로 배포할지
